# 科技侠错误码中英文映射

适用于 Populife Android 后端返回 `code=960`，且 `msg` 为包含 `errcode` 的 JSON 字符串的响应。中文和英文使用同一错误原因映射，具体提示由 App 语言资源决定。

本表补齐《Populife错误码文案与状态处理规范-给开发.md》的错误码映射，包含官方 52 个错误码，以及原规范保留的 `-1026`，共 53 个。仅实现业务码与文案映射，不增加状态机、查询确认或重试控制。

## 来源

核对日期：2026-10-12。

- [科技侠中文错误码文档](https://cnopen.ttlock.com/document/doc?urlName=cloud%2FerrorCode.html)，[正文](https://cnopen.ttlock.com/documentPages/htmlPages/cloud/errorCode.html)。
- [科技侠英文错误码文档](https://euopen.ttlock.com/document/doc?urlName=cloud%2FerrorCodeEn.html)，[正文](https://euopen.ttlock.com/documentPages/htmlPages/cloud/errorCodeEn.html)。

官方中英文表的 52 个错误码完全一致。下方中文和英文为面向用户的 App 文案，结合原规范改写，不是官方技术说明的逐字翻译。

## 原规范遗漏与修正

原规范遗漏 44 个官方错误码，其中 `-3` 已在代码中实现，本次新增其余 43 个：

`10000`, `10001`, `10003`, `10011`, `10007`, `30002`, `30003`, `30004`, `30005`, `30006`, `30008`, `80000`, `80002`, `-3`, `-2018`, `-4063`, `-1003`, `-2025`, `-3011`, `-4067`, `-4082`, `-1008`, `-1016`, `-1018`, `-1027`, `-2019`, `-2020`, `-2023`, `-4064`, `-1007`, `-2009`, `-3006`, `-3007`, `-3008`, `-3009`, `-3002`, `-3003`, `-3016`, `-3034`, `-3035`, `-3036`, `-4037`, `-1021`, `-1023`。

- `-3037`：官方为“锁忙”，原规范的“网关暂时不可用”应改为“锁正忙”。网关忙对应 `-3003`。
- `-4043`：官方为“此锁不支持该操作”，适用于所有调用场景，不能限定为远程开锁。
- `-3006`：中文官方要求 4–9 位，英文官方要求 6–9 位；双语提示统一为长度不符合要求，不写死位数，也不据此修改输入校验。
- `-2009`：中文为密码不存在，英文为密码无效，合并表述为“不存在或已失效”；与 `10007` 的服务账号验证失败区分。
- `10003`、`10004`、`10011`：均为科技侠上游授权问题。当前 App 登录自有后端，未发现能保证刷新上游授权的客户端逻辑，提示联系客服，不承诺重新登录可恢复。
- `80000`：是服务请求时间偏差，不能直接认定手机时间错误。
- `-4056`：保留密码、指纹、门卡三种提示；凭证类型未知时仍明确提示存储空间已满。
- `-1026`：本次两份官方列表均未列出，沿用原规范已确认的映射。

## 映射规则

1. 仅当外层 `code` 为数值 `960` 时，解析 `msg` 字符串中的数值 `errcode`。其他外层业务码沿用页面原有处理。
2. 已知错误码使用下表的对应提示。`1` 使用原有通用提示；`0` 不作为错误映射。
3. 未知错误码、缺少字段或 JSON 无法解析时，保留页面原有兜底提示，不把原始技术说明展示给用户。
4. 保留原有状态、操作及重试逻辑，不增加自动重试、删除、重置或清空动作。
